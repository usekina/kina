# KinaBot V1 Pilot Plan

## Pilot Goal

KinaBot V1 will run as a small, consent-based public-benefit pilot for speech and language-based cognitive wellness reflection.

The goal is to help users observe speech, language, and communication features over time while protecting privacy, dignity, and responsible-use boundaries.

KinaBot is designed for individuals, families, and caregivers who want to better understand speech and language patterns over time. One important use case is supporting older adults and families with respectful, consent-based reflection.

KinaBot does not provide medical diagnosis, cognitive disease screening, dementia risk prediction, or treatment recommendations.

## Pilot Scope

- Up to 100 pilot users
- 90-day pilot period
- Maximum 2 tests per user per day
- Web-based access through a browser
- Email verification code required before testing
- No raw audio storage by default
- No transcript storage by default
- Store only calculated feature scores and minimal usage records

## What V1 Measures

V1 will calculate multiple speech and language feature scores, not a single medical score.

Potential feature categories include:

- Vocabulary variety
- Sentence complexity
- Speech pace
- Response length
- Repetition pattern
- Emotional tone
- Pause or silence pattern
- Transcription clarity

These scores are intended for cognitive wellness reflection, personal awareness, and trend observation, not diagnosis.

## Data Handling

KinaBot V1 should store:

- Hashed user email or anonymous user ID
- Test timestamp
- Session number for the day
- Calculated feature scores
- Consent version
- App version

KinaBot V1 should not store by default:

- Raw audio files
- Full transcripts
- Medical history
- Family member information
- Personal notes

Users should be able to request deletion of their records.

## User Access

Users will request access with an email address.

The system will send a one-time verification code.

Each verified user may complete up to 2 tests per day.

The verification system helps:

- Limit server cost
- Count active users
- Prevent uncontrolled public use
- Support responsible pilot management
- Create evidence of real-world usage

## User Output

Users should receive:

- Speech and language-based cognitive wellness reflection
- Feature-level scores
- Trend view over time
- Respectful, non-alarming explanations
- Optional downloadable report

The output should not provide:

- Medical diagnosis
- Cognitive age
- Dementia risk
- Disease prediction
- Treatment recommendation

## Pilot Success Metrics

The pilot may track:

- Number of registered users
- Number of active users
- Number of completed tests
- 7-day, 30-day, and 90-day retention
- Average tests per user
- Number of generated trend views
- User feedback
- Deletion requests
- System cost per test

## Future Direction

After V1, future versions may explore:

- Better feature models
- Improved visualization
- Family/caregiver sharing with consent
- Local or private speech-to-text options
- Clinical or academic review
- Separate commercial versions with appropriate compliance review
